## 제품 방향

모듈 1을 교사용 발표 자료가 아니라, 수업 뒤 학생에게 건네면 스스로 확인하고 경험할 수 있는 탐구 도구로 고도화했다. 화면마다 학생이 다음 세 가지를 바로 알 수 있게 구성했다.

1. 지금 무엇을 하는가
2. 왜 이 행동을 하는가
3. 이 행동이 어떤 AI 리터러시와 연결되는가

## 주요 변경

### 공통 학생 UX

- 모듈 1에만 적용되는 `studentMode` 헤더를 추가했다.
- 모듈 1에서는 `교사 도구`, `발표 화면`, 상단 활동지 버튼을 숨기고 `도움말`을 제공한다.
- 다른 모듈의 `AppHeader` 기본 동작은 바꾸지 않았다.
- 활동 시작 화면에 학습 브리프를, 모든 단계에 `지금 할 일 / 왜 할까요?` 안내를 추가했다.
- 모듈 1 내부 타이포그래피를 학생 화면 기준으로 상향하고 직접 지정된 11~13px 글자를 제거했다.
- 기존의 강한 파랑·민트 계열을 따뜻한 편집물 테마에 맞는 저채도 색으로 조정했다.

### 금쪽이 스피커 연결

- 두 활동 시작에 실제 금쪽이 챗봇과 말해 볼 프롬프트를 제공한다.
- 학생은 `금쪽이와 대화했어요` 또는 `준비된 응답으로 계속하기` 중 하나를 고를 수 있다.
- 웹앱이 음성을 녹음하거나 실제 기기 API에 직접 연결한다고 오해하지 않도록 명시했다.
- 스피커가 없는 환경에서도 동일한 학습 흐름을 완주할 수 있다.

### 활동 추천 실험

- AI의 첫 추천을 본 뒤 학생이 `이유`, `빠진 기록`, `다른 가능성` 중 하나를 되묻게 했다.
- 준비된 응답은 실제 생성형 AI가 아니라 학습용 시뮬레이션임을 표시했다.
- 빠진 오프라인·관심 기록을 추가한 전후 답변을 비교하도록 했다.
- 마지막 O/X 정답 퀴즈를 제거했다.
- 4가지 확인 항목과 학생의 최종 행동 선택으로 활동을 마치게 했다.
- 과학 추천, 코딩 후보 유지, 당사자에게 직접 묻기 모두 이유를 살펴 선택할 수 있다.

### 대표팀 공정성 실험

- AI 추천 결과에 `왜 이 네 명인지`, `빠진 역할`, `참여 기회`를 질문하게 했다.
- 이의제기 화면에서 특정 정답만 골라야 진행되던 잠금을 제거했다.
- 결과 유지, 데이터 정정 후 재계산, 한 사람만 예외 적용의 결과를 모두 탐색할 수 있다.
- 데이터·공통 기준·재검토 절차를 분리해 판단하도록 설명을 보강했다.

### 완료와 오프라인 연결

- 완료 화면을 일반 요약 대신 학생의 실제 선택이 반영된 `AI 리터러시 탐구 기록`으로 바꿨다.
- 활동별 배지 `데이터 탐험가`, `공정성 감시자`를 추가했다.
- 짝과 선택을 비교하고 금쪽이 스피커에 다른 관점을 다시 요청하는 오프라인 후속 활동을 제안했다.
- 활동지 미리보기가 화면에서 숨겨질 수 있던 기존 표시 문제를 수정했다.
- 활동지에 학생이 고른 질문, 최종 행동, 이의제기 대응을 반영했다.

## 상태 호환성

- 기존 스토리지 키 `ai-literacy-lab:v5`를 유지했다.
- 다음 화이트리스트 필드를 추가했다.
  - `growthSpeakerPath`
  - `growthQuestionId`
  - `growthFinalChoice`
  - `teamSpeakerPath`
  - `teamQuestionId`
- 기존 저장 데이터에 새 필드가 없어도 `null`로 안전하게 보완된다.
- 허용되지 않은 값은 저장 상태 검증에서 제거된다.
