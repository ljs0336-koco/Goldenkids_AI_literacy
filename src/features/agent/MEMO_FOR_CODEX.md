# 모듈 4 유지보수 메모

현재 모듈 4는 학생이 수업 뒤 스스로 체험하는 흐름으로 재구성되어 있습니다.

## 학생 경험

- 활동 A ‘공연 초대를 보내도 될까?’
  - 학생 동아리 홍보팀의 공동 계정과 확인된 연계학교 연락처를 사용합니다.
  - AI의 공유 가능한 행동 기록을 한 장씩 확인합니다.
  - 받는 사람·공연 정보·최종 포스터·연락처 공개 범위를 확인한 뒤 A/B를 고릅니다.
  - 작은 C 선택지로 시험 전송을 살펴볼 수 있습니다.
  - 활동 뒤 HITL(Human-in-the-Loop)을 AI 준비 → 사람 확인·결정 → AI 실행 → 사람 결과 확인으로 정리합니다.
- 활동 B ‘사라지는 견학 사진을 멈춰라’
  - 박물관 견학 보고서용 공유 앨범을 정리하는 상황입니다.
  - 부탁하지 않은 휴지통 이동과 영상 삭제 예약을 찾아 비상 정지합니다.
  - 비상 정지는 새 행동만 막으며, 이미 바뀐 파일은 복구·권한 회수·기록 확인이 필요합니다.
  - 원본 읽기 전용, 복사본 정리, 확인 필요 분리, 영향이 큰 행동 전 HITL을 설정합니다.

## 구조

- agentData.js: 동아리 초대 미션, 박물관 자료 사고, 네 가지 안전 설정
- agentEngine.js: 데이터 조회와 안전 설정 완료 여부 계산. 안전 점수·백분율은 만들지 않습니다.
- useAgentState.js: 독립 저장소 ai-literacy-lab-agent:v3와 화이트리스트 검증
- components/: 페이지 안내, A/B 선택, 페이지 이동, 학생 도움말
- screens/mission/: 상황 → 행동 기록 → 전송 전 확인 → HITL 정리
- screens/control/: 이상 행동·정지 → 복구 → 안전 설정 → 내 원칙

## 회귀 방지

- 교사 도구와 발표 모드를 학생 화면에 다시 넣지 않습니다.
- 숨겨진 추론을 공개한다고 표현하지 않습니다. 계획·도구 요청·관찰 결과처럼 공유 가능한 기록만 보여 줍니다.
- AI가 스스로 권한을 얻는다고 표현하지 않습니다. 사람이 넓게 허용한 권한 안에서 목표를 과도하게 해석하는 문제로 설명합니다.
- 사람 승인만으로 안전을 보증하지 않습니다. 판단 정보, 보류 가능성, 실행 후 확인을 함께 둡니다.
- 비상 정지가 과거 결과까지 자동 복구한다고 표현하지 않습니다.
- 스토리지 스키마를 바꿀 때는 새 버전을 만들고 src/utils/learningProgress.js 초기화 목록에 추가합니다.
