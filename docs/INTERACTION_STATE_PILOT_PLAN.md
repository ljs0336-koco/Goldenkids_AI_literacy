# 클릭 반응형 활동 무대 시범 적용 계획

작성일: 2026-08-24  
상태: 구현 전 설계안  
시범 대상: 모듈 2 `진짜일까? 써도 될까?`

## 1. 목적

현재의 `읽기 → 선택 → 다음` 흐름을 학생의 행동에 따라 화면의 상태가 분명하게 달라지는 체험으로 바꾼다.

학생은 각 장면에서 다음 네 가지를 바로 알아볼 수 있어야 한다.

1. AI가 한 일은 무엇인가.
2. 지금 내가 해야 할 일은 무엇인가.
3. 내가 누른 뒤 무엇이 달라졌는가.
4. 사람이 확인하거나 결정한 결과가 어디에 남았는가.

점수와 보상을 중심으로 한 게임은 만들지 않는다. 대신 `선택 → 변화 → 확인 → 완료`의 손맛을 제공한다.

## 2. 시범 모듈 선정

모듈 2를 시범 대상으로 선정한다.

- 이미 페이지 단계, A/B 선택, 완료 상태가 구현되어 있어 콘텐츠를 다시 만들지 않고 상호작용을 검증할 수 있다.
- `AI 초안`, `확인 전`, `사람이 고친 결과`가 분명해 공통 역할 라벨을 시험하기 좋다.
- 상단 `지금 할 일`과 하단 안내 팝업의 중복 문제를 함께 해결할 수 있다.
- 기사 검증과 미디어 게시 판단이라는 서로 다른 활동에서 같은 상호작용 문법이 유지되는지 확인할 수 있다.

시범 구현은 두 차례로 나눈다.

1. 활동 A `학교신문 AI 초안 검증`을 먼저 완성하고 사용감을 확인한다.
2. 승인된 문법을 활동 B `미디어 게시 전 확인`에 적용해 모듈 2 전체를 완성한다.

활동 A 확인 전에는 모듈 1·3·4의 코드를 변경하지 않는다.

## 3. 공통 상호작용 문법

모든 장면은 다음 순서를 따른다.

```text
장면 등장 → 한 가지 행동 제시 → 학생 클릭 → 화면 안에서 결과 변화
         → 역할·상태 라벨 갱신 → 다음 장면 활성화
```

### 3.1 장면 등장

- 이전 콘텐츠는 쌓아 두지 않고 현재 장면 하나만 보여 준다.
- 제목, 현재 할 일, 판단할 대상, 행동 버튼의 순서를 유지한다.
- 새 장면은 고정된 활동 무대 안에서 짧게 옆에서 들어온다.
- 첫 진입 시 현재 눌러야 할 요소의 테두리와 작은 손가락 표시가 한 번만 강조된다.

### 3.2 학생 행동

- 한 장면의 주 행동은 하나만 둔다.
- A/B 선택은 성격이 구분되는 테두리와 옅은 배경을 사용한다.
- 필요한 경우에만 작은 `다른 판단 보기` 버튼으로 C를 연다.
- 아직 필요한 행동을 하지 않았다면 `다음` 버튼은 비활성화하고 이유를 버튼 문구에 적는다.

### 3.3 즉각적인 변화

- 선택한 버튼은 눌린 상태와 체크 표시가 즉시 나타난다.
- 결과는 하단 팝업이 아니라 같은 활동 무대의 예약된 결과 영역에 나타난다.
- 학생이 고친 문장, 남긴 자료, 게시 결정 등 실제 대상이 바뀌어야 한다.
- 선택 결과가 나타날 때 화면 전체 높이가 늘어나지 않도록 결과 영역을 미리 확보한다.

### 3.4 완료

- 의미 있는 판단을 마쳤을 때만 완료 라벨을 짧게 활성화한다.
- `사람 확인 완료`, `함께 완성` 같은 완료 표시는 한 장면에 한 번만 강조한다.
- 완료 효과 후 다음 장면 버튼이 활성화된다.

## 4. 화면 골격

모듈 2의 각 페이지는 다음 네 영역을 유지한다.

```text
┌──────────────────────────────────────────┐
│ 진행 단계                                │
├──────────────────────────────────────────┤
│ 지금 할 일                         [?]   │
├──────────────────────────────────────────┤
│ 역할 라벨 · 현재 상태                    │
│                                          │
│            현재 활동 장면                │
│                                          │
│            선택 결과 영역                │
├──────────────────────────────────────────┤
│ 이전                      다음/완료       │
└──────────────────────────────────────────┘
```

### 4.1 고정의 의미

- 데스크톱에서는 활동 무대와 결과 영역에 단계별 최소 높이를 둔다.
- 콘텐츠 길이가 다른 장면으로 바뀌어도 헤더와 하단 행동 버튼의 위치가 크게 움직이지 않게 한다.
- 모바일에서는 고정 픽셀 높이를 강제하지 않고 자연스럽게 늘어나도록 한다.
- 긴 내용을 작은 내부 스크롤 상자에 가두지 않는다.

즉, 모든 화면을 같은 높이로 억지로 자르는 것이 아니라 `제목·작업 대상·결과·버튼`의 자리를 예약해 시각적 흔들림을 줄인다.

## 5. 역할과 상태 라벨

라벨은 `누가 했는가`와 `어디까지 확인했는가`를 분리한다.

### 5.1 작업 주체

| 라벨 | 의미 | 기본 표현 |
|---|---|---|
| AI 초안 | AI가 먼저 만든 결과 | 차분한 청록색 |
| 사람 판단 | 사람이 직접 고르거나 결정 | 따뜻한 황토색 |
| 함께 완성 | AI 결과를 사람이 확인·수정 | 짙은 녹색 |

### 5.2 현재 상태

| 라벨 | 의미 | 형태 |
|---|---|---|
| 확인 전 | 아직 사람이 확인하지 않음 | 중립색 테두리 |
| 확인 중 | 자료를 읽고 판단하는 중 | 황토색 테두리 |
| 사람 확인 완료 | 근거 확인과 판단 완료 | 녹색 채움 |
| 수정 필요 | 그대로 사용할 수 없음 | 붉은색이 아닌 따뜻한 갈색 경고 |

향후 모듈 4에서는 같은 체계에 `승인 필요`, `승인 완료`, `중지됨`을 추가한다. 시범 구현 중에는 모듈 4를 수정하지 않는다.

### 5.3 라벨 표시 원칙

- 색만으로 의미를 구분하지 않고 아이콘과 한글 문구를 함께 쓴다.
- 라벨 위치는 모든 장면에서 동일하게 유지한다.
- 완료 순간에만 0.2초 안팎의 짧은 도장 효과를 사용한다.
- `FACT/FAKE`처럼 강한 판정 효과는 실제 사실 판정 결과에만 사용하고, 작업 주체 라벨과 혼용하지 않는다.

## 6. 챗봇·AI 체험 표시

현재 모듈 2는 실제 챗봇과 연결되어 있지 않다. 미리 준비된 AI 답변을 사용하는 로컬 시뮬레이션이다.

시범 화면에는 다음 정보를 명시한다.

```text
AI 역할 · 기사 초안 작성 도움
체험 방식 · 미리 준비된 AI 답변을 검증하는 가상 체험
```

실제 챗봇 이름은 임의로 만들지 않는다. 연결 기능을 추가할 수 있도록 모듈 내부 설정은 다음 상태를 구분할 수 있게 설계한다.

- `simulation`: 미리 준비된 사례
- `connected`: 실제 챗봇 연결
- 실제 챗봇 이름
- 실행 링크 또는 QR 정보

연결 전에는 `연결된 챗봇`이라는 문구를 사용하지 않는다. 연결 후에만 다음 형식으로 교체한다.

```text
연결된 챗봇 · 실제 확정된 챗봇 이름
```

## 7. 활동 A 상세 흐름

### 장면 1. AI 초안 도착

- 시작 라벨: `AI 초안` + `확인 전`
- `초안 작성 도움: AI 금쪽이`를 문서 푸터가 아닌 상단 작업 라벨로 명확히 표시한다.
- 시뮬레이션 안내를 작은 정보 줄로 함께 표시한다.
- 주 행동: `검증 시작하기`
- 클릭 후 기사 카드가 왼쪽으로 물러나고 문장 선택 장면이 들어온다.

### 장면 2. 확인할 문장 선택

- 기사 전체를 반복해서 보여 주지 않고 문장을 한 장씩 보여 준다.
- 문장 카드를 누르면 `지금 확인할 문장`으로 활성화된다.
- 이미 완료한 문장은 `사람 확인 완료` 꼬리표가 남는다.
- 주 행동: 문장 카드 클릭

### 장면 3. 자료 봉투 열기

- 닫힌 자료 봉투를 누르면 작성자·날짜·내용이 같은 자리에서 열린다.
- A `비교할 자료로 남기기`와 B `이번 비교에서 빼기`를 선택한다.
- 선택 후 자료 카드에 `비교에 남김` 또는 `이번 비교에서 제외` 상태가 표시된다.
- 하단 팝업은 띄우지 않는다.

### 장면 4. 자료 비교

- 남긴 자료를 한 장씩 옆으로 넘긴다.
- 각 자료를 읽은 뒤 진행 표시가 채워진다.
- 마지막 자료까지 확인하면 요약 장면으로 전환되고 `판정하기`가 활성화된다.

### 장면 5. 문장 판정과 수정

- 시작 라벨: `AI 초안` + `확인 중`
- A/B 판정을 누르면 선택 버튼이 고정되고 이유 선택 영역이 같은 자리에서 들어온다.
- 이유를 누르면 AI 초안 문장이 실제로 검증 문장으로 교체된다.
- 완료 라벨: `함께 완성` + `사람 확인 완료`
- 완료 라벨 활성화 후 `기사에 반영하기`가 열린다.

### 장면 6. 기사 완성

- 검증 전과 검증 후 기사를 나란히 비교한다.
- 검증 후 기사에는 `함께 완성`과 `사람 확인 완료`를 표시한다.
- 학생이 한 행동을 `자료 선택 → 비교 → 판정 → 수정` 네 단어로 요약한다.

## 8. 활동 B 상세 흐름

활동 A가 승인된 뒤 같은 골격을 적용한다.

### 장면 흐름

1. 게시 요청 도착
2. 화면에서 확인할 단서 선택
3. 제작자·변경 내용·동의 정보 열기
4. 권리와 사용 조건 판단
5. 게시 여부 결정
6. 처음 요청과 최종 결정 비교

### 라벨 흐름

```text
AI 합성 사용 정보 + 사람 확인 전
→ 제작 정보 확인 중
→ 사람의 게시 결정
→ 사람 확인 완료
```

AI 합성 콘텐츠라는 이유만으로 `가짜`라고 판정하지 않는다. 보이는 단서, 출처, 맥락, 동의와 사용 조건을 차례로 확인하게 한다.

## 9. 안내 체계 정리

### 유지

- 상단 `지금 할 일`
- 물음표 안의 `왜 이 활동을 하는지`
- 헤더의 전체 도움말

### 제거

- 장면이 열릴 때 자동으로 나타나는 하단 `지금 해볼 일` 팝업
- 페이지 넘김과 선택 직후 같은 지시를 반복하는 팝업
- 본문과 하단 버튼에서 같은 행동을 두 번 설명하는 문장

### 대체

- 클릭 결과는 활동 무대 안의 고정 결과 영역에 표시한다.
- 새 장면에서는 눌러야 할 요소를 한 번만 짧게 강조한다.
- 오류나 누락은 해당 요소 바로 옆에 간결하게 표시한다.

## 10. 애니메이션 기준

새 라이브러리를 설치하지 않고 React 상태와 CSS로 구현한다.

| 동작 | 효과 | 권장 시간 |
|---|---|---|
| 새 장면 진입 | 12~18px 이동 + 투명도 변화 | 220~280ms |
| 버튼 선택 | 짧게 눌렸다 복귀 | 100~140ms |
| 결과 등장 | 아래에서 6~10px 이동 + 투명도 변화 | 180~240ms |
| 완료 라벨 | 1.06배에서 원래 크기로 정착 | 220~280ms |

- 동시에 여러 요소를 움직이지 않는다.
- 반복 애니메이션과 자동 재생 장식은 사용하지 않는다.
- `prefers-reduced-motion: reduce` 환경에서는 이동 효과를 제거하고 즉시 상태를 바꾼다.
- 애니메이션이 끝나야만 정보를 읽을 수 있는 구조를 만들지 않는다.

## 11. 시범 구현 범위

시범 단계에서는 `src/features/verification/**`만 수정한다.

예상 구성 요소:

- `VerificationExperienceStage`: 고정 활동 무대와 장면 전환
- `VerificationWorkLabels`: 작업 주체와 확인 상태
- `VerificationInlineFeedback`: 예약된 결과 영역
- `VerificationActionDock`: 이전·다음·완료 행동 영역

이름과 개수는 구현 전 기존 컴포넌트와 겹치는지 다시 확인한다.

시범 단계에서는 다음을 하지 않는다.

- `src/components/**` 공용 컴포넌트 변경
- 다른 모듈의 안내 팝업 제거
- 실제 챗봇 백엔드 또는 외부 링크 연결
- 점수, 레벨, 배지 수집, 폭죽 효과 추가
- 교육 내용과 사례의 대규모 재작성
- 새 애니메이션 라이브러리 설치
- 로컬스토리지 키 또는 기존 학습 기록 형식 변경

검증 후에만 공통 구성 요소를 `src/components/**`로 승격한다.

## 12. 접근성·사용성 기준

- 모든 클릭 요소는 키보드로 이동하고 실행할 수 있어야 한다.
- 선택 상태는 `aria-pressed` 또는 동등한 상태 정보로 전달한다.
- 장면 전환 후 화면 읽기 도구에는 새 장면 제목을 알린다.
- 상태 변화 알림은 짧은 문구 하나만 사용한다.
- 모바일 터치 영역은 최소 44px을 유지한다.
- 색을 보지 않아도 아이콘과 문구로 상태를 이해할 수 있어야 한다.
- 뒤로 이동해도 이미 남긴 판단은 유지한다.

## 13. 검증 체크리스트

### 자동 테스트

- 한 화면에 `지금 할 일` 안내가 하나만 존재한다.
- 초기 기사에 `AI 초안`, `확인 전`, `가상 체험`이 보인다.
- 선택 전에는 다음 행동이 비활성화된다.
- A/B를 선택하면 같은 장면 안에서 결과가 나타난다.
- 이유 선택 후 `함께 완성`, `사람 확인 완료`로 바뀐다.
- 뒤로 갔다 돌아와도 저장된 판단이 유지된다.
- 기존 16개 모듈 2 통합 시나리오의 교육 논리가 유지된다.
- 학생 화면과 인쇄물에 차시 번호가 나타나지 않는다.

### 수동 확인

- 데스크톱에서 선택 전후 카드와 버튼 위치가 크게 흔들리지 않는다.
- 모바일에서 콘텐츠가 잘리거나 이중 스크롤이 생기지 않는다.
- 빠르게 여러 번 눌러도 중복 장면이나 잘못된 완료 상태가 생기지 않는다.
- 뒤로 가기, 전체 초기화, 홈 이동이 정상 작동한다.
- 모션 감소 설정에서 애니메이션 없이도 모든 상태를 이해할 수 있다.

- 역할·상태 라벨

- 중복 하단 안내 제거

### 2단계. 활동 A 세로 완성

- 초안 도착부터 기사 완성까지 전 흐름 적용
- 자동 테스트와 데스크톱·모바일 수동 확인
- 사용자 검토용 ZIP 생성

이 지점에서 실제 사용 피드백을 받는다. 다음 항목을 우선 확인한다.

- 무엇을 눌러야 하는지 설명 없이 알 수 있는가.
- 클릭한 뒤 무엇이 바뀌었는지 바로 보이는가.
- `AI 초안`과 `사람 확인 완료`의 차이가 기억에 남는가.
- 움직임이 집중을 돕는가, 방해하는가.

### 3단계. 활동 B 확장

- 승인된 상호작용 문법만 미디어 흐름에 적용
- 기사 활동과 동일한 위치·문구 체계 유지
- 모듈 2 전체 회귀 테스트

### 4단계. 전체 모듈 확장 결정

모듈 2 사용 피드백을 반영한 뒤 공통 컴포넌트 승격 여부를 결정한다.

## 15. 향후 모듈별 적용 방향

| 모듈 | 학생 행동으로 바뀌어야 할 핵심 대상 | 완료 라벨 예시 |
|---|---|---|
| 1 | AI의 첫 진로 추천에 새로운 정보를 더해 추천을 다시 판단 | 내가 다시 판단 |
| 2 | AI 초안을 자료로 검증하고 문장을 수정 | 함께 완성 · 사람 확인 완료 |
| 3 | AI에게 맡길 역할을 바꾸어 응답과 역할 분담을 비교 | 역할 선택 완료 |
| 4 | AI의 행동 계획을 확인하고 승인·중지·복구 | 사람 승인 완료 / 중지됨 |

모듈마다 소재와 결론은 다르게 유지하되, `내가 눌렀기 때문에 대상과 상태가 변한다`는 체험 문법만 공유한다.

## 16. 완료 정의

시범 적용은 다음 조건을 모두 만족할 때 완료로 본다.

1. 학생이 팝업 지시 없이 현재 행동을 찾을 수 있다.
2. 선택 결과가 화면 안에서 즉시 보인다.
3. AI가 한 일과 사람이 확인한 일을 라벨로 구분할 수 있다.
4. 화면의 주요 영역이 선택 전후에 크게 움직이지 않는다.
5. 애니메이션을 꺼도 학습 흐름이 온전하다.
6. 실제 챗봇 연결 여부를 오해하지 않는다.
7. 기존 테스트, 전체 테스트, 린트와 빌드가 통과한다.
