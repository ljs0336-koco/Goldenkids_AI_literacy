> 작업 범위: 모듈 3 `src/features/role/**`, 홈의 모듈 3 소개, 역할 저장 키 초기화 목록

## 개편 목표

- AI를 학업이나 과업에 적극적으로 써 보지 않은 학생도 첫 화면에서 활용 장면을 이해한다.
- 긴 콘텐츠 목록 대신 한 화면에서 한 가지 행동을 하고 다음 장으로 넘긴다.
- 선택은 A/B 두 갈래를 중심으로 보여 주고, 제3안은 작은 보조 버튼으로 연다.
- 학생이 한 활동을 끝내기 전부터 개념어를 외우게 하지 않고, 먼저 비교하고 선택하게 한다.
- 단순 규칙 자동화를 AI라고 부르지 않고 자동화·AI 도움·사람 결정을 구별한다.

## 새 모듈 구조

### 활동 A · AI에게 어떻게 부탁할까?

1. 마음 정리, 아이디어 시작, 쉬운 설명, 발표 점검 중 상황 하나를 고른다.
2. 역할을 말하지 않은 평범한 AI 답과 상황을 먼저 본다.
3. 같은 부탁에 대한 A/B 역할 답을 읽고 지금 필요한 도움을 고른다.
4. 다른 답이 필요하면 작은 버튼을 눌러 C안을 연다.
5. 두 역할의 순서를 정해 `역할 + 할 일 + 조건과 순서`가 들어간 부탁 문장을 완성한다.
6. 체험 뒤에야 이 부탁 문장을 ‘프롬프트’라고 설명한다.
7. 상황 하나를 마치면 활동을 완료하고, 나머지 세 상황은 선택 체험으로 추천한다.

금쪽이 스피커 연결은 부탁 문장을 완성한 화면에서 한 번만 짧게 제안한다.

### 활동 B · AI에게 어디까지 맡길까?

1. 계산기, 번역 앱, 사람의 결정처럼 익숙한 도구 사용부터 살펴본다.
2. 정해진 규칙 자동화가 모두 AI는 아니라는 차이를 확인한다.
3. 학교 축제라는 하나의 맥락에서 네 가지 일을 차례로 나눈다.
   - 축제 신청 명단 정리
   - 축제 소개 문구 초안
   - 외국어 안내문 초벌 번역
   - 축제 부스 주제 최종 선택
4. 각 일마다 A `규칙으로 자동 정리`, B `사람이 직접 결정` 중 먼저 고른다.
5. 필요하면 C `AI가 돕고 사람이 확인`을 연다.
6. 선택 직후 같은 화면에서 `도구의 일 → 사람 확인 → 책임`을 확인하고 다음 일을 누른다.
7. 마지막에는 비율이나 점수 대신 `AI·자동화 → 사람 확인 → 수정 → 사람 최종 결정` 역할 지도를 완성한다.

## 화면과 안내

- 모듈명은 `AI에게 무엇을 맡길까?`로 바꾸었다.
- 모든 주요 화면 위에 `지금 할 일`과 선택형 `왜 할까요?` 안내를 둔다.
- 주요 단계가 바뀔 때 7초 안내 토스트가 뜬다.
- 학생용 헤더에는 홈, 전체 초기화, 도움말만 보이고 교사 도구와 발표 모드는 숨긴다.
- 데스크톱 활동 무대는 최소 높이를 유지하고, 선택 결과·제3안·프롬프트·과업 결과 자리를 미리 확보한다.
- 브라우저 측정에서 활동 A 선택 전후 높이는 `931.31px`, 활동 B 선택 전후 높이는 `942.27px`로 동일했다.
- 모바일 390px 검증에서 가로 넘침이 없었다.

## 데이터와 저장 상태

- 새 상태는 선택한 역할, 상황별 부탁 조합, 현재 과업, 분석 페이지, 한 가지 원칙을 화이트리스트로 검증한다.

## 팩트·표현 정비

- AI가 공감 표현을 만들 수 있어도 감정을 실제로 느끼는 것은 아니라고 명시했다.
- ‘설명 박사’는 실제 전문가가 아니라 설명 방식의 이름이라고 안내했다.
- 블랙홀을 모든 것을 빨아들이는 ‘우주의 청소기’로 단정하지 않았다.
- 근거 없는 시간 비율과 통계 표현을 제거했다.
- ‘인간만의 고유 능력’ 같은 절대 표현 대신 영향을 받는 사람, 상황, 책임을 묻게 했다.
